DOCKER & DOCKER COMPOSE — QUICK REFERENCE
==========================================
A practical, beginner-friendly cheat sheet for working with this project's
Docker setup (Dockerfile + docker-compose.yml).

This project runs 6 services via Compose: postgres, redis, migrate
(one-shot, applies Alembic migrations), fastapi-app, celery-worker,
celery-beat, and flower.


1. FIRST-TIME SETUP
--------------------
Copy the Docker env template and fill in real secrets before starting
anything. Use .env.docker.example, NOT .env.example — the Docker one
points at the "postgres" and "redis" service names instead of localhost:

    cp .env.docker.example .env.docker

Then build and start everything:

    docker compose up -d --build

  -d      = "detached", runs in the background instead of blocking your terminal
  --build = force-build the image before starting (use on first run or after
            changing the Dockerfile/dependencies)


2. EVERYDAY WORKFLOW
---------------------
Start all services (uses existing images if already built):

    docker compose up -d

Stop all services (containers are removed, volumes/data are kept):

    docker compose down

Stop services but keep containers so they can be quickly resumed:

    docker compose stop
    docker compose start

Restart a single service (e.g. after tweaking an env var):

    docker compose restart fastapi-app


3. REBUILDING AFTER CODE CHANGES
----------------------------------
The fastapi-app, celery-worker, celery-beat, and migrate services bind-mount
your local folder into the container and run with --reload, so most Python
code edits are picked up automatically — no rebuild needed.

You DO need to rebuild when you change:
  - Dockerfile
  - pyproject.toml / uv.lock (dependencies)

To rebuild:

    docker compose up -d --build

To force a clean rebuild ignoring Docker's build cache:

    docker compose build --no-cache
    docker compose up -d


4. VIEWING LOGS
-----------------
Tail logs for every service:

    docker compose logs -f

Tail logs for one service:

    docker compose logs -f fastapi-app

  -f = "follow", keeps streaming new log lines (Ctrl+C to stop)

See only the last N lines:

    docker compose logs --tail=100 celery-worker


5. RUNNING COMMANDS INSIDE A CONTAINER
-----------------------------------------
Open a shell inside a running container:

    docker compose exec fastapi-app bash

Run a one-off command without a full interactive shell (e.g. a migration
or a management command):

    docker compose exec fastapi-app /app/.venv/bin/alembic upgrade head

Run a command in a NEW container even if the service isn't already running
(rarely needed here since `migrate` already handles migrations):

    docker compose run --rm fastapi-app /app/.venv/bin/alembic current


6. CHECKING STATUS
--------------------
List running containers for this project:

    docker compose ps

Show resource usage (CPU/memory) live:

    docker stats


7. CLEANING UP
----------------
Stop and remove containers + the default network (data volumes kept):

    docker compose down

Also remove named volumes (THIS DELETES the Postgres database data):

    docker compose down -v

Remove dangling/unused images, containers, and build cache to free disk space:

    docker system prune

Remove a specific image:

    docker rmi <image_id_or_name>

List all images / containers (including stopped ones) to find IDs:

    docker images
    docker ps -a


8. TYPICAL DAY-TO-DAY FLOWS
------------------------------
Start working for the day:

    docker compose up -d
    docker compose logs -f fastapi-app

Pulled new code with dependency changes:

    docker compose up -d --build

Something's stuck / behaving weirdly, want a totally fresh start:

    docker compose down
    docker compose up -d --build

Inspect the database directly:

    docker compose exec postgres psql -U postgres -d tododb

Done for the day:

    docker compose down


9. QUICK COMMAND GLOSSARY
----------------------------
docker build .              Build an image from a Dockerfile in the current dir
docker run <image>          Start a single container from an image
docker ps                   List running containers
docker ps -a                List all containers, including stopped ones
docker images                List locally available images
docker stop <container>     Gracefully stop a running container
docker rm <container>       Remove a stopped container
docker rmi <image>          Remove an image
docker logs <container>     View logs for a single container (non-Compose)
docker exec -it <c> bash    Open a shell inside a running container

docker compose up -d        Start all services in the background
docker compose down         Stop and remove all services
docker compose build        Build/rebuild images defined in docker-compose.yml
docker compose ps           List this project's running services
docker compose logs -f      Follow logs across all services
docker compose exec <svc>   Run a command inside a running service's container
docker compose restart <s>  Restart a single service
